# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev      # astro dev — http://localhost:4321
npm run build    # astro build — outputs ./dist (fully static)
npm run preview  # serve the built site locally
npm run check    # astro check — type-check .astro + .ts (no separate test suite exists)
```

There is no test runner, linter, or formatter configured. `npm run check` is the only correctness gate.

`SITE_URL` is build-time critical — it is baked into the sitemap, `og:url`, and `<link rel="canonical">`. Always pass it for production builds:

```bash
SITE_URL=https://yourdomain.com npm run build
```

Docker build mirrors this via `--build-arg SITE_URL=...` (see `Dockerfile`).

## Architecture

**Static-only Astro site.** `astro.config.mjs` sets `output: 'static'` and `trailingSlash: 'never'`. There is no server runtime, no API routes, no client islands — every page is pre-rendered HTML at build time. Production is served by nginx (`Dockerfile` → `nginx.conf`).

**Tailwind CSS v4 via Vite plugin, not a config file.** Theme tokens (colors, fonts) are declared in `src/styles/global.css` under `@theme { ... }`. There is no `tailwind.config.js` — adding one will not be picked up. Custom CSS variables (`--color-bg`, `--color-accent`, etc.) are referenced from components as `bg-[var(--color-bg)]` / `text-[color:var(--color-accent)]`.

**Single source of truth for profile data: `src/data/site.ts`.** `site`, `social`, `skills`, and `experience` are typed exports consumed by every section component. To change the developer's name, role, links, or work history, edit this file — do not duplicate strings into components.

**Projects are a content collection, not a hardcoded array.** Schema lives in `src/content.config.ts` (Zod-validated). Each project is a markdown file in `src/content/projects/<slug>.md` with frontmatter (`title`, `tagline`, `description`, `stack[]`, `year`, `featured`, `draft`, optional `repo`/`demo`/`image`/`role`). The slug becomes the URL: `/projects/<slug>`. The page route `src/pages/projects/[...slug].astro` uses `getStaticPaths()` to pre-render one HTML file per non-draft project. The home page `Projects.astro` section also reads from this collection.

**SEO and JSON-LD are centralized in two places:**
- `src/layouts/BaseLayout.astro` is the only HTML shell. Every page uses it and passes `title`, `description`, `canonicalPath`, `type`, `noindex`, `jsonLd`.
- `src/components/SEO.astro` always emits `Person` and `WebSite` JSON-LD blocks plus per-page blocks passed via the `jsonLd` prop. The home page adds an `ItemList` of projects; project pages add a `CreativeWork`. When adding a new page, pass any page-specific structured data through `jsonLd` rather than emitting `<script type="application/ld+json">` ad hoc.

**Sitemap** is generated by `@astrojs/sitemap` at build time (`sitemap-index.xml`). It uses the `site` value from `astro.config.mjs`, so `SITE_URL` must be correct at build time or sitemap entries will point at `example.com`.

## Conventions

- Components are `.astro` server components — no React/Vue. Inline `<script>` is allowed but the site is designed to work fully without JS.
- Prefer editing `src/data/site.ts` and adding markdown files in `src/content/projects/` over creating new components or routes.
- Strict TypeScript (`astro/tsconfigs/strict` + `strictNullChecks`). Run `npm run check` after non-trivial edits.
- `404.astro` sets `noindex`; do not remove that flag.
